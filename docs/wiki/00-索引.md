# TikTok B2B Bot — 开发者 WIKI 索引

> 版本: 0.6.2-hermes-h1 | 最后更新: 2026-08-08

## 变更摘要（v0.6.2-hermes-h1）

- 新增受认证的 `POST /api/acquisition/jobs`：Pipeline Job、Campaign 和 1—100 个初始关键词
  在同一事务提交，避免 Dispatcher 先认领到缺少获客定义的 queued Job
- AI 获客阶段必须是六阶段的严格有序子序列且包含 `collect`；`configSnapshot` 在 API 与
  Service 两层递归拒绝凭据类键，错误不回显敏感键值
- AI 获客重试统一从 `collect` 开始，并在同一事务克隆 Campaign 与关键词定义；新执行的
  使用次数、视频数、候选数等计数从 0 开始，legacy 重试语义保持不变
- `BusinessReadModel` 将任务级资格、分类、评分和证据投影到 Users、Lead、Dashboard、
  Reports Overview 与关键词图表；AI 结论不反写全局 `User.status/category`
- 关键词效果按 AI Evidence 与 legacy 来源词的不同用户实时聚合，不信任可能过期的计数器；
  Lead 直接使用 0..100 AI 匹配分，报告和词云返回真实数据契约
- H1 后端全量回归 `733 passed`；租户隔离仍是 P0 上线阻断，H2 创建表单和 H3 复核工作台
  不在本阶段范围内

## 变更摘要（v0.6.1-stage02）

- 阶段 02 使用公开字段白名单、严格资格契约、双评分、多标签和四状态人工复核；AI 的通过
  与淘汰都只作为建议，只有人工操作能写 `qualified/rejected`
- 人工版本 CAS 防止耗时 LLM 结果覆盖人工通过/淘汰；候选与策略使用 keyset 分页，移除
  固定前 200/100 条造成的饥饿
- Campaign 策略采用严格 `StrategyResult`；模型自由话术由确定性中性模板替换，危险或无效
  输出不落库、不触达；阶段 03/04 均再次检查当前 Job、平台和人工合格状态
- 多账号数据隔离经只读审计升级为 P0 上线阻断，明确 T1—T5 实施顺序；本版本尚未宣称
  多租户安全

## 分阶段实施状态（v0.5.0）

- ✅ **抖音交互登录核心 Provider 已完成**：账号级隔离的有头持久化浏览器只打开抖音
  首页，由用户在真实浏览器中完成扫码、短信或滑块；核心层不自动点击、不提取二维码，
  也不再使用整页截图充当二维码
- ✅ **登录态核心持久化已完成**：抖音保存独立 Playwright Profile 与含 IndexedDB 的
  storage state；路径防碰撞、私密目录权限、账号租约与 `LoginSession` 状态机已落地
- ✅ **统一交互登录核心 Service 已完成**：`start/status/verify/cancel/aclose` 统一管理
  start、共享 verify operation、超时、浏览器资源和账号租约；挂起操作可取消，关闭失败
  保留租约并支持重试
- ✅ **提交边界与关闭语义明确**：账号更新事务启动后由事务结果决定 confirmed/failed，
  timeout/cancel 不伪造回滚；pending commit/open reaper 或清理失败时 shutdown 返回
  `login_cleanup_incomplete` 并保持可重试 closing 状态
- ✅ **TikTok 指纹边界已完成**：仅 nominal 指纹适配器可通过专用 Registry 入口注册，
  且必须与账号 Provider/Profile 绑定；普通 Playwright 和字符串伪装均 fail-closed
- ✅ **交互登录 API 核心已完成**：四个会话端点统一调用 `InteractiveLoginService`，
  生产接线复用浏览器 Registry，登录会话内部共用 `AccountLeaseManager`；响应采用
  凭据白名单，账号更新在单个事务中提交，服务关闭会执行 `aclose()`
- ✅ **账号 alias 规范与冲突边界已统一**：添加账号、登录请求、resolver、浏览器隔离键

  扫描与提交，历史等价 alias 多行时稳定返回 `account_alias_conflict`，不任取一行
- ✅ **首次登录遵守全局账号上限**：新 alias 在打开浏览器前执行只读容量预检，并在
  updater 的 `BEGIN IMMEDIATE` 事务中再次检查，防止并发或 TOCTOU 绕过 `MAX_ACCOUNTS`；
  已有账号在满额时仍可更新，满额新账号稳定返回 `account_limit_reached`
- 🚧 **Pipeline 账号租约接线仍待后续 Task**：当前登录会话已具备稳定的账号互斥，
  但 Pipeline/登录共用同一个 `AccountLeaseManager` 尚未完成，不宣称已跨系统互斥
- ✅ **旧 QR API 已安全降级**：旧创建/状态端点转发同一 Service 并标记 deprecated，
  不再返回二维码或路径字段；图片端点固定返回 410 且不读取文件

- ⏳ **具体 TikTok 厂商适配待后续阶段**：当前只有严格接口与不可用占位，仍需接入

- ✅ **LLM Router 数据层已完成**：`llm_providers / llm_routes /

## 变更摘要（v0.4.0）

- ✨ **统一 Pipeline 任务系统**：TikTok 与抖音共用
  `pipeline_jobs / pipeline_job_stages / pipeline_schedules`、同一组 REST API、
  同一个 `/pipeline` 页面和同一份任务历史；手动与定时执行都进入 SQLite 队列
- ✨ **平台与账号选择统一**：任务和计划都显式保存 `platform`、
  `accountMode(auto/specified)`、`accountId` 与阶段列表；CLI 也只创建同一种持久化任务
- ✨ **运行边界明确**：抖音每个任务使用独立 Playwright Context，并按
  `douyin_max_concurrency`（1..20）限制并发；TikTok 必须配置指纹浏览器 Provider，
  默认返回 `fingerprint_provider_unavailable`，不会回退到普通 Playwright
- ✨ **可靠执行**：支持阶段持久化、取消、从失败阶段重试、启动恢复和任务内用户/
  策略/消息隔离；触达预留保证同一任务不会自动重复发送不确定消息
- ✨ **统一计划管理**：五段 cron + 时区 + 启停的计划 CRUD；调度器只补建最近一次
  错过的运行，创建出的仍是普通 Pipeline Job
- ✨ **主页链接持久化**:`users.profile_url` (VARCHAR 500) + 幂等迁移;
  后端按 platform + username 兜底拼接,前端 Users / UserDetail 表格直接渲染可点外链
- ✨ **聚合统计同源**:`/api/users/stats` 增加 `rejected` / `new_today` / `by_persona`,
  前端 subtitle / KPI / 状态 chip / 画像 chip 全部走单一权威源,不再"碰巧对得上"
