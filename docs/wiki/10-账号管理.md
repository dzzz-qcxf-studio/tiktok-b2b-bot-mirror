## 设计目标

登录不再把“自动点击登录、截取二维码或整页截图”当作主流程。新的核心设计提供：

1. **人工完成平台风控** — 打开可见的账号专属浏览器，用户自行完成扫码、短信、滑块
   或平台要求的其他验证。
2. **账号级浏览器隔离** — 每个抖音账号使用独立持久化 Profile，避免 Cookie、
   localStorage、IndexedDB 和浏览器状态串号。
3. **双重登录态持久化** — 同时保留 Profile 和 Playwright storage state，后续可复用
   已完成验证的真实浏览器状态。
4. **服务端会话核验** — 不以截图、URL 或单个访客 Cookie 作为登录成功证据。
5. **账号互斥** — 全部交互登录会话共用账号租约；检测与 Pipeline 接入同一租约管理器
   属于后续 Task，完成前不宣称跨系统互斥。
6. **平台边界清晰** — 抖音使用本地 Playwright 持久化上下文；TikTok 必须使用指纹
   浏览器 Provider，不能回退到普通 Playwright。
7. **身份与展示分离** — `username` 是稳定的浏览器隔离 alias；用户可单独编辑
   `display_name` 本地备注，不移动或重命名既有 Profile/storage state。
8. **展示资料可信同步** — 抖音只有在官方同源身份探针验证成功后，才同步平台昵称、
   HTTPS 头像和粉丝数；不从页面任意 DOM 或用户输入伪造平台资料。

    └── persist()                  # 内部复验后原子保存 storage state

`LoginSession` 管理
`launching → waiting_user → verifying → persisted → confirmed` 等受约束状态；
只有 Provider 验证成功且登录态成功持久化后才允许确认。过期会话不能被确认。

`InteractiveLoginService` 不在持锁状态下等待外部 Provider 或数据库操作。每个 token
共享一个可取消的 verify operation task：并发 verify 复用同一个结果，单个调用方取消
不会取消共享操作；服务级 cancel、超时或 shutdown 才会终止操作。Service 同时登记
start、timeout 和资源清理任务，确保关闭期间不再接受新 start，resolver、可用性检查或
浏览器 open 的晚返回资源也会被纳管并关闭。
即使唯一 verify 调用方在等待期间取消，底层 operation 自行过期或失败后也会通过受
跟踪的终态 maintenance task 完成浏览器关闭和租约释放，不依赖调用方回来收尾。

浏览器关闭与租约释放采用分阶段、可重试清理：只有 Context 确认关闭成功后才释放账号
租约。首次关闭失败时保留浏览器引用和租约，并记录 `browser_cleanup_failed`；后续
cancel 或 `aclose()` 可以安全重试，避免尚在运行的浏览器与 Pipeline 同时占用账号。

账号更新是明确的提交边界：Provider 验证和登录态持久化成功后，Service 才启动独立、
受跟踪且 shielded 的账号更新事务。一旦事务启动即视为 **commit-won 阶段**，后来的
timeout、cancel 或 shutdown 只能等待事务结果，不能把可能已经提交的账号状态伪装成
`expired/cancelled`。事务成功时会话最终为 `confirmed`，失败时为 `failed`。若事务或
open reaper 在 shutdown grace 内仍未结束，`aclose()` 返回稳定错误
`login_cleanup_incomplete`，保持 closing 且拒绝新 start；后台资源完成后可重试关闭。
同步与异步账号 updater 都在同一独立 commit task 内调用；同步回调抛错同样规范化为
`account_update_failed`，不会泄露原始异常或遗留浏览器和账号租约。

## 抖音核心登录流程

1. 获取账号租约，计算该账号独立的 Profile 与 storage state 路径。
2. 使用 `launch_persistent_context(headless=False)` 打开持久化 Chromium。
3. 只导航到 `https://www.douyin.com/`，不自动点击登录，不抓取二维码，也不截图。
4. 用户在真实浏览器中自行登录并完成扫码、短信、滑块等验证。
5. 用户确认完成后，Provider 请求同源服务端探针
   `/aweme/v1/web/user/profile/self/?device_platform=webapp&aid=6383&...`，
   必须带 `device_platform=webapp`、`aid=6383`、`pc_client_type=1` 等 webapp
   客户端参数；裸 URL 即使对已登录会话也会返回 `status_code=8`「用户未登录」。
6. 探针必须返回 `status_code == 0`，并提供非空 `uid` 或 `sec_uid`。
7. 探针通过后再读取仅限 `https://www.douyin.com/` 的 Cookie，校验域、有效期、
   非空认证会话标记（`sessionid/sessionid_ss/sid_guard`）。抖音 PC web 已登录
   时并不下发 `LOGIN_STATUS`，缺失不能判为未登录；只有平台明确下发
   `LOGIN_STATUS=0` 才是确定的未登录信号。
8. `persist()` 内部再次执行完整验证，验证通过后保存 Profile 与
   `storage_state(indexed_db=True)`。

`ttwid`、`msToken`、`uid_tt` 可能存在于未登录访客会话，不能单独作为登录成功条件。
`localStorage.HasUserLogin` 仅可作为诊断信息，不能替代服务端探针。

## 账号检测（check-session）

`POST /api/accounts/{aid}/check-session` 当前只通过抖音服务端身份探针验证账号是否仍然
登录。TikTok 暂无同等可靠探针时返回 `valid: null`、`supported: false` 和稳定码
`session_check_unsupported`，保持数据库中的原账号状态，不能把“不支持检测”误判为过期。

抖音检测流程如下：

1. 在数据库 session 内读取 `cookies_json` 并立即转字符串，**不把 ORM 对象带出
   session**，避免 `DetachedInstanceError` 被静默吞掉导致误判离线。
2. 启动 `BrowserClient`，**先**导航到 `https://www.douyin.com/`（about:blank 下
   Playwright 拒绝 secure cookie，且探针 fetch 不被识别为同源请求），再注入
   全部 Cookie。
3. 走与交互登录相同的 webapp 探针 URL，要求 `status_code == 0` 且 user 含非空
   `uid`/`sec_uid`。
4. 探针验证通过后，从同一 `user` 对象提取昵称、粉丝数，以及
   `avatar_thumb/avatar_medium/avatar_larger.url_list` 中首个合法 HTTPS URL，更新账号展示资料；
   某字段缺失或无效表示“未知”，保留数据库旧值，不以空字符串或 0 覆盖。
5. 只读主页 URL 含 "login" 已过时，不能作为离线判据；已登录会话的 SPA 路由也
   可能停在 `/jingxuan`、`/follow` 等子路径。
6. 失败原因以白名单 `profile_*` / `cookie_consistency_failed` /
   `homepage_*` 诊断码返回到前端，区别于通用的 `interactive_login_failed`。

## 持久化与路径安全

- 浏览器账号键固定为规范化的 `platform:accountAlias`，与数据库自增 ID 分离；新 alias
  入库前后始终使用同一键，纯数字 alias 不会被当成数据库 ID。
- 所有账号 alias 共用 `normalize_account_alias()`：执行 Unicode NFKC 与首尾空白清理，
  保留大小写并拒绝空值；账号新增、登录请求、resolver、隔离键和 updater 不再各自实现
  不同的清理规则。
- 同平台新增账号和登录首次入库使用 SQLite `BEGIN IMMEDIATE`，在同一写事务中完成
  规范化冲突扫描、账号上限检查和插入。并发 `A`/`Ａ` 或 `foo`/` foo ` 只有一个写入
  成功，另一个稳定返回 `account_alias_conflict`。
- 零匹配新 alias 在打开浏览器前执行全局账号容量预检；updater 在写锁事务中按
  “alias 冲突优先、全局 count、insert”再次检查，不能通过并发验证绕过
  `MAX_ACCOUNTS`。已有账号即使满额也可更新，满额新账号返回
  `account_limit_reached`。
- 账号目录名使用可读 slug 加 SHA-256 摘要，避免中文账号、特殊字符账号清洗后碰撞。
- Profile 与 storage state 均按平台、账号隔离。
- POSIX 私密目录使用 `0700`，状态文件使用 `0600`。
- Windows 使用 `GetUserNameExW(NameSamCompatible)` 读取当前进程令牌身份，再通过
  `icacls` 收紧 Profile 与认证状态目录的 ACL。不能使用 `USERNAME`/`getpass` 作为
  主判断，因为模拟运行、服务账号或提权进程的环境用户名可能与实际令牌身份不同；
  权限收紧失败时记录明确的降级告警，不静默忽略。
- storage state 采用临时文件加原子替换，避免进程中断留下半写文件。
- Playwright 最低版本支持 `storage_state(indexed_db=True)`，因此 IndexedDB 与
  Cookie/localStorage 一并保存。

## API/UI 迁移状态

当前阶段已完成 API 与前端人工浏览器登录接线：

- `POST /api/accounts/login-sessions`、`GET /api/accounts/login-sessions/{token}`、
  `POST .../{token}/verify` 和 `POST .../{token}/cancel` 均调用同一个
  `InteractiveLoginService`。
- 状态响应只包含 token、平台、账号、安全状态、到期时间和公开浏览器标识；不包含
  Cookie、storage state、Profile 绝对路径、浏览器对象或二维码字段。
- 既有 `/api/accounts/login-qrcode` 与 `/api/accounts/login-status` 已转发新 Service
  并标记 deprecated；二维码图片端点固定返回 410，且不会读取 token 对应的文件。
- 生产 resolver 支持既有账号和新 alias；updater 在单个数据库事务内保存兼容 Cookie
  快照、登录状态、相对认证路径、验证时间、版本和实际浏览器元数据。任何提交失败都会
  回滚并产生 `account_update_failed`，不会返回虚假 confirmed。
- resolver 会扫描同平台全部账号并用统一规则比较：零条时创建待登录快照，一条时精确
  使用该账号，多条历史等价 alias 时 fail-closed 返回 `account_alias_conflict`；
  零条且全局满额时在浏览器打开前返回 `account_limit_reached`。updater 在插入或覆盖前
  重复冲突与容量验证，绝不插入第六条或任意覆盖冲突账号。
- Provider availability/adapter 的未知错误码在 Service 边界被归一化；API 对会话和
  异常码再次应用公开白名单，未知码不会进入响应或日志。
- 应用 shutdown 会调用 Service `aclose()`；`login_cleanup_incomplete` 明确记录并向上
  返回，保留可重试语义。
- `src/api/index.ts` 的四个类型化会话方法由 `InteractiveLoginModal.vue` 统一使用。
  Modal 不渲染二维码、截图、token、Cookie 或路径；用户在平台浏览器完成验证后必须
  主动点击“验证并保存登录状态”，只有 `confirmed` 才让父页面刷新账号和能力列表。
- Modal 切平台、关闭或卸载时先幂等取消非 confirmed 会话；异步请求使用 generation
  守卫，迟到创建的 token 也会立即取消。确认成功的会话不会被卸载清理误取消。
- 账号页对已有账号重登传递 `accountId + accountAlias`，新账号使用可编辑 alias；
  TikTok 指纹 Provider 不可用等公开错误在 `aria-live` 状态区解释，不展示响应中的
  其他任意字段。
- `PUT /api/accounts/{aid}` 只接受最长 100 字符的 `displayName`；清空表示恢复使用
  平台昵称。该接口不会修改 `username`、平台昵称、头像、Cookie 或浏览器路径。
- 抖音登录确认事务和 `POST /api/accounts/{aid}/check-session` 都会在身份探针成功后同步
  平台昵称、真实头像与粉丝数。头像只接受长度不超过 1000 的 HTTPS URL；前端图片使用
  `referrerpolicy=no-referrer`，加载失败时回退为名称首字占位。
- 抖音头像 CDN 地址带有 `x-expires/x-signature`，不能作为永久展示地址。登录核验或
  `check-session` 在已验证浏览器仍打开时立即下载头像，只接受可信的
  `douyinpic.com/byteimg.com` HTTPS 主机、JPEG/PNG/WebP 文件头且最大 1 MiB；图片以原子写
  缓存到 Git 忽略的 `data/account_avatars/`。下载失败不影响登录确认，也不会删除上一份缓存。
- `GET /api/accounts` 同时返回平台原始 `avatar_url` 和派生的 `avatar_data_url`；账号页优先
  使用本地缓存，原始短期 URL 仅作首次同步前的回退。删除账号会同步删除缓存文件。
- TikTok 检测在可靠同源身份探针接入前返回“不支持”且不修改状态；批量检测会单独统计
  暂不支持的账号，不把它们计为过期。

## 安全注意事项

1. **不向前端返回 cookies** — 前端只管理不含凭据的会话标识和状态。
2. **登录 IP 检测** — TikTok 会做 IP 风控，常用账号在固定 IP 登录更安全
3. **频繁掉线检测** — 自动检测 status 从 logged_in → expired，触发重新登录
4. **账号互斥** — `AccountLeaseManager` 当前防止交互登录会话彼此占用同一账号；
   检测与 Pipeline 共用该管理器尚待后续接线。
5. **目录权限降级可见** — Windows ACL 或 POSIX 权限设置失败必须发出告警并记录路径，
   便于部署者修复。

## 与 Pipeline Provider 的关系

交互登录与 Pipeline 执行使用同一张账号表，但 Provider 生命周期不同：

- `DouyinInteractiveLoginProvider` 当前负责人工登录、核验和保存登录态。
- 既有 `DouyinPlaywrightProvider` 负责 Pipeline 执行。让 Pipeline 完整消费新的
  Profile/storage state 属于后续服务接线阶段，不能仅因 Task 3 完成就宣称已端到端复用。
- Pipeline 运行时当前尚未持有交互登录的 `AccountLeaseManager`；跨登录/Pipeline 的
  账号互斥必须等后续接线完成后才能验收。
- TikTok 任务必须先在代码中接入并向 Registry 注册具体指纹浏览器适配器，再为账号
  配置该适配器要求的 Provider/Profile。当前项目只有通用接口和
  `UnavailableFingerprintProvider` 默认占位；只填写数据库字段不会解锁任务。
- TikTok 交互适配器必须 nominal 继承 `FingerprintInteractiveLoginProvider`，通过
  `register_tiktok_fingerprint_interactive()` 注册，并校验账号 `browser_provider`
  与适配器 `provider_id` 一致且 `browser_profile_id` 非空；可伪造的字符串标记不能
  绕过该边界。
- TikTok 未配置时能力接口与任务预检返回
  `fingerprint_provider_unavailable`，不会回退到普通 Playwright。

## 失败场景处理

| 场景 | 处理 |
|------|------|
| Playwright 未安装 | 启动时 RuntimeError 给出安装提示 |
| 浏览器版本不匹配 | 提示运行 `playwright install chromium` |
| 用户未完成登录 | 会话超时/取消，关闭浏览器并释放账号租约 |
| 探针失败或返回未登录 | 保持未确认状态，不持久化新的登录态 |
| Cookie 域错误、已过期或缺少登录标记 | 验证失败，不以页面截图或 URL 猜测成功 |
| storage state 写入失败 | 不允许 `LoginSession` 进入 confirmed |
| 浏览器打开阶段异常/取消 | 关闭持久化 Context，避免 Profile 锁泄漏 |
| Provider verify/persist 挂起 | cancel、超时或 shutdown 取消共享 operation，再关闭浏览器并释放租约 |
| 账号更新事务已经启动 | timeout/cancel 等待事务；成功后 confirmed，失败后 failed，不伪造回滚 |
| shutdown grace 内 commit/reaper 未结束 | 返回 `login_cleanup_incomplete`，保持租约并允许后续重试关闭 |
| 浏览器首次关闭失败 | 标记 `browser_cleanup_failed`，保留租约和资源供后续重试 |
| TikTok 未配置指纹 Provider | 返回 `fingerprint_provider_unavailable`，不回退 Playwright |
