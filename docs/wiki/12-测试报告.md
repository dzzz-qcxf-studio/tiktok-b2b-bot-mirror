## DeepSeek 密钥认证现场诊断（2026-08-01）

- 密钥通过受鉴权的 Provider Secret API 写入项目根目录 `.env` 中的
  `DEEPSEEK_API_KEY`；Provider 数据库记录只保存环境变量名，不保存密钥正文。
- API 进程使用 `--env-file .env` 启动，Secret API 返回 HTTP 200，并在写入后关闭旧
  LLM Router，使下一次请求重新读取当前密钥。
- 应用内 Provider 连接测试返回 HTTP 200，但结果为 `reachable=false`、
  `errorCategory=authentication`。
- 绕过本项目、使用同一枚密钥直连 DeepSeek 官方余额接口，返回 HTTP 401，错误类型为
  `authentication_error`。因此当前认证失败定位为上游拒绝该凭据，不是前端登录、密钥
  落盘路径或 Router 缓存问题。
- 本报告不记录密钥正文、前后缀或其他可用于还原凭据的信息。

## v0.5.9 浏览器旧 token 自动恢复（2026-08-01）

- 二次根因：路由守卫只判断 `localStorage.token` 是否存在，不判断能否被服务器验签；
  失效 token 因此仍可进入模型页，保存时只在表单中显示 401，用户无法完成恢复。
- 修复：受保护请求 401 时清除旧会话并跳转登录，携带安全站内返回地址；登录成功后
  自动回到原页面。登录/注册自身错误不会触发该拦截器。
- 安全：返回地址拒绝外部 URL、双斜杠和登录页自身，避免开放重定向与登录循环。
- 并发安全：401 只可清理该失败请求实际携带的同一枚当前 token；迟到旧请求不会覆盖
  更新后的登录状态。
- RED：测试先因缺少 `authSession.ts` 失败；并发用例随后真实复现“旧 401 删除新 token”；
  两轮实现后失效会话与模型配置共 14 passed。

## Task 6 人工浏览器登录 UI 增量验收（2026-07-29）

本轮删除旧 `QRScanModal.vue`，账号页统一使用 `InteractiveLoginModal.vue` 和 Task 5

  必须先取消旧会话并重新打开浏览器，不能用错配 alias 验证。
- verify 只由用户按钮触发；未登录仍停留等待态，只有 `confirmed` 发出 success，
  confirmed 组件卸载不会发送 cancel。
- 关闭、Escape、切平台与卸载对非 confirmed token 幂等 cancel；既有账号保持原平台，
  不会把同一个 account ID 错误切到另一平台。
- 轮询使用严格非重入的 `setTimeout → await → finally 再调度`，任何时刻最多一个状态
  请求在途；generation 与 poll epoch 会让 verify、关闭、切平台和卸载后的迟到结果
  失效。首个 deferred 未返回时推进多个周期也不会产生第二个请求。
- 状态应用层把 `confirmed/failed/expired/cancelled` 作为不可逆终态；同一 session 一旦
  进入终态，任何迟到 nonterminal 快照都不能覆盖，confirmed success 仍只发出一次。
- alias 在输入、props 变化、create payload、响应采纳和 success 事件中统一执行
  NFKC + trim；全角 alias 使用服务端 canonical 形式，显式全空白不会创建会话。

- verify/persist/account update 挂起时，cancel、timeout 和 `aclose()` 可在有界时间内
  取消 operation、关闭浏览器并释放租约。
- `aclose()` 与 resolver、availability、open 的 start 竞态；包括 Provider 吞取消后
  late return 的浏览器仍会被关闭。
- cancel/timeout/confirm/shutdown 竞态不会重复 close、persist、account update 或
  release。
- 浏览器 close 首次失败不会释放租约；后续 cancel/`aclose()` 重试成功后才释放。
- `LoginSession`、内部 managed resource repr 和 asyncio task name 不泄露 token、
  Cookie 或私密路径。
- verify 或 persist 刚越过 deadline 时由 operation 返回 expired snapshot，外层完成
  close/release，不会自取消并抛出 `CancelledError`。
- 账号 updater 启动后进入 commit-won：timeout/cancel 等待同一事务，成功 confirmed、
  失败 failed；pending commit 的 `aclose()` 有界返回 `login_cleanup_incomplete`。
- open 吞取消且暂不返回时，start 在短 grace 后由 reaper 接管并有界失败；reaper 完成
  前租约保持占用，`aclose()` 报 incomplete，晚返回浏览器关闭后重试成功。
- 同步与异步账号 updater 统一在受跟踪 commit task 内执行；同步成功只提交一次，
  同步抛错稳定返回 `account_update_failed` 并完成 close/release。
- 唯一 verify 等待者取消后，底层 operation 自行过期仍由终态 maintenance task
  完成 close/release，不依赖公开调用方恢复等待。
