# 11 — 双平台支持（TikTok + 抖音）

> 关联: [索引](00-索引.md) | [账号管理](10-账号管理.md) | [Plugin 层](04-Plugin层.md)
> 最后更新: 2026-07-29

## 设计目标

让同一套 Job、Stage、Schedule、API 和 UI 同时管理 TikTok（国际版）与抖音
（中国版）。平台只是任务字段和 Provider 分派条件，不是两套系统。

## 核心抽象：`Platform` (`platforms.py`)

```python
@dataclass(frozen=True)
class Platform:
    name: str
    home_url: str
    search_user_url_tpl: str           # 关键词搜索模板
    user_profile_url_tpl: str          # 用户主页模板
    login_url: str                     # 登录页 URL
    selectors: dict[str, str]          # 平台专属 CSS 选择器

    def search_user_url(self, keyword): ...     # 自动 URL 编码
    def user_profile_url(self, username): ...
```

## 预定义平台

### TikTok（`TIKTOK`）

| 项 | 值 |
|----|----|
| `home_url` | `https://www.tiktok.com/` |
| 搜索 URL | `https://www.tiktok.com/search?q={kw}&type=user` |
| 用户主页 | `https://www.tiktok.com/@{username}` |
| 登录页 | `https://www.tiktok.com/login` |
| username 路径前缀 | `/@` |
| 视频 URL 特征 | `/video/` |

### 抖音（`DOUYIN`）

| 项 | 值 |
|----|----|
| `home_url` | `https://www.douyin.com/` |
| 搜索 URL | `https://www.douyin.com/search/{kw}?type=user` |
| 用户主页 | `https://www.douyin.com/user/{username}` |
| 登录入口 | `https://www.douyin.com/`（打开首页后由用户自行点击并完成验证） |
| username 路径前缀 | `/user/` |

## 关键差异点

| 差异 | TikTok | 抖音 |
|------|--------|------|
| 域名 | tiktok.com | douyin.com |
| 搜索 URL | `?q=kw&type=user` | `/{kw}?type=user` |
| 用户主页 URL | `/@username` | `/user/{sec_user_id}` |
| 评论按钮 | `data-e2e="comment-post"` | `button:has-text("发送")` |
| 私信按钮 | `data-e2e="message-btn"` | `button:has-text("私信")` |
| 可靠登录 cookie | sessionid/sessionid_ss/sid_guard | sessionid/sessionid_ss/sid_guard |
| Pipeline 浏览器 | 指纹 Provider（需配置） | 独立 Playwright Context |
| 默认可执行 | 否，稳定 blocked | 有已登录账号时可执行 |

## 数据模型改动

```sql
-- users 表加 platform 列
ALTER TABLE users ADD COLUMN platform VARCHAR(20) DEFAULT 'tiktok';

-- tiktok_accounts 表加 platform 列
ALTER TABLE tiktok_accounts ADD COLUMN platform VARCHAR(20) DEFAULT 'tiktok';
```

交互登录持久化还为 `tiktok_accounts` 增加以下字段：

| 字段 | 作用 |
|------|------|
| `storage_state_path` | Playwright storage state 文件路径 |
| `profile_path` | 持久化浏览器 Profile 路径 |
| `auth_verified_at` | 最近一次通过平台服务端验证的时间 |
| `auth_version` | 登录态格式版本 |
| `browser_provider` | TikTok 指纹浏览器 Provider 标识（既有字段） |
| `browser_profile_id` | TikTok 指纹浏览器 Profile ID（既有字段） |

`tiktok_id` 字段从原本的纯 username 改为 `{platform}:{username}` 复合主键，避免跨平台 username 冲突。

ORM 也持久化了 `users.profile_url`(VARCHAR(500)),与 `Platform.user_profile_url()` 互补:

- Platform 抽象 — **运行时**由浏览器自动化层用,生成待访问 URL
- profile_url 列 — **持久化**用户主页链接,前端 Users / UserDetail 表格直接渲染

写入时若 profile_url 为空,API 层会按 platform + username 兜底拼接
(TikTok → `https://www.tiktok.com/@<u>`,抖音 → `https://www.douyin.com/user/<u>`)

## 业务调用模式

业务代码通过 Platform 抽象自动适配：

```python
from tiktok_bot_core.platforms import get_platform, PlatformType

pf = get_platform("tiktok")  # 或 "douyin"
url = pf.search_user_url("importer")
await browser.navigate(url)

# 视频选择器自动使用平台对应的
sel = pf.selectors["comment_post"]
btn = await browser.query(sel)
```

业务代码不需要写 `if platform == "tiktok": ... else: ...`。

## 统一 Pipeline 任务示例

```json
{
  "platform": "douyin",
  "accountMode": "auto",
  "accountId": null,
  "stages": ["collect", "filter", "strategy", "outreach"],
  "configSnapshot": {
    "keywords": ["进口商", "批发商"]
  }
}
```

相同 payload 可提交到 `POST /api/pipeline/jobs`；CLI 的 `pipeline run` 和定时
Scheduler 最终也调用 `PipelineJobService.create_job()`。计划与手动执行都会写入
`pipeline_jobs`，所以任务历史、取消、重试和恢复完全一致。

## Browser Provider 与并发

`BrowserProviderRegistry` 是唯一 Provider 查找入口：

- `douyin → DouyinPlaywrightProvider`：每次 acquire 都创建独立 Client/Context
  并注入所选账号 Cookie；`douyin_max_concurrency` 控制平台总并发（1..20），
  账号锁保证单账号互斥。并发设置保存后需重启 Runtime 生效。
- `tiktok → UnavailableFingerprintProvider`（默认）：固定返回
  `fingerprint_provider_unavailable`。项目尚未绑定具体指纹浏览器厂商；未来适配器
  必须在代码中实现统一的 check/acquire/release 契约并通过 Registry 注册，然后再
  按适配器要求配置账号 Profile。只填写 `browser_provider/browser_profile_id` 字段
  不会替换默认 Provider，也不会解锁 TikTok 任务。

这里没有 “TikTok 失败就使用 Playwright” 的分支。

## 交互登录 Provider 与统一 Service（Task 3–4 阶段）

Pipeline Browser Provider 和交互登录 Provider 是两个生命周期边界，不能混为一谈。
当前已完成 `DouyinInteractiveLoginProvider` 的核心实现：

- 有头持久化 Context 只打开抖音首页，用户自行完成扫码、短信、滑块等平台验证。
- 不自动 click，不从页面源代码提取二维码，也不生成二维码或整页截图兜底。
- 每个账号使用独立 Profile；目录名使用 slug + SHA-256 摘要避免特殊字符碰撞。
- 登录验证先请求同源
  `/aweme/v1/web/user/profile/self/`，要求 `status_code == 0` 且存在 `uid` 或
  `sec_uid`；随后再校验 scoped Cookie 的域、有效期、认证会话标记与
  `LOGIN_STATUS`。
- 持久化前执行内部复验，成功后保存
  `storage_state(indexed_db=True)` 和账号专属 Profile。
- 账号私密目录在 POSIX 上使用 `0700`、状态文件使用 `0600`；Windows 上通过
  `icacls` 收紧 ACL，权限降级会明确告警。
- `AccountLeaseManager` 与 `LoginSession` 核心组件已落地，防止账号并发占用和非法
  状态跃迁。
- `InteractiveLoginService.start/status/verify/cancel/aclose` 已成为统一核心入口；
  并发 verify 共享同一 operation，cancel、超时和 shutdown 可中断挂起 Provider，
  并清理浏览器、timeout task 与账号租约。
- 唯一 verify 等待者取消不会取消共享 operation；若 operation 随后自行过期或失败，
  受跟踪的终态 maintenance task 仍会关闭浏览器并释放租约。
- Registry 已明确分离 Pipeline 与 Interactive Provider 生命周期。TikTok 交互适配器
  必须 nominal 继承 `FingerprintInteractiveLoginProvider`，通过专用入口注册，并让
  `provider_id` 与账号配置匹配且 Profile ID 非空；普通 Playwright 或字符串伪装会
  稳定返回 `fingerprint_provider_unavailable`。
- start 与 Service shutdown 的竞态已纳入生命周期管理；resolver、availability 或
  open 阶段被取消时不会遗留晚返回浏览器或 timeout task。
- 浏览器 close 失败时不会提前释放账号租约；资源保留并以
  `browser_cleanup_failed` 等待后续 cancel/`aclose()` 重试。
- Provider persist 成功并启动账号更新事务后进入 commit-won 阶段。此后 timeout、
  cancel 和 shutdown 不再取消事务或标记 expired/cancelled：事务成功最终 confirmed，
  失败最终 failed，避免数据库已提交而会话状态声称已回滚。
- 同步和异步账号 updater 使用同一 commit task 生命周期；同步抛错也稳定转换为
  `account_update_failed` 并执行资源清理。
- open 吞取消且未在短 grace 内返回时由 tracked reaper 接管，reaper 关闭晚返回浏览器
  前租约保持占用。pending commit/reaper 或清理失败会让 `aclose()` 返回
  `login_cleanup_incomplete`；Service 保持 closing、拒绝新 start，资源完成后可重试。

阶段边界：

- FastAPI 兼容端点仍保留一个迁移周期，但账号页已改用 `InteractiveLoginModal.vue`
  和四个会话 API；UI 不再渲染二维码或截图，人工验证完成后才请求保存。
- Task 4 的统一核心 Service 与 TikTok 指纹适配边界已完成；项目尚未绑定具体指纹
  浏览器厂商，因此 TikTok 当前仍稳定返回不可用，绝不回退普通 Playwright。
- Task 5 的 FastAPI 会话端点已与前端人工浏览器窗口接线。
- Pipeline 对新 Profile/storage state 的完整消费仍需后续接线。

## 数据隔离与恢复

- `PipelineRunContext` 强制携带 job/platform/account/browser_session。
- `pipeline_job_users` 隔离每次任务的筛选/画像/触达状态。
- Strategy、Message、ExperienceRule 记录 job_id；向量经验带 platform/job_id metadata。
- 触达先写发送预留，异常为 uncertain，不自动二次发送。
- 取消在阶段边界生效；失败/中断任务通过新 Job 从失败阶段重试。

| Collector | TikTok | 抖音 | 说明 |
|-----------|--------|------|------|
| KeywordCollector | ✅ | ✅ | 双平台 URL 切换 |
| RecommendationCollector | ✅ | ✅ | 双平台用户主页路径切换 |
| CompetitorCollector | ✅ | ⚠️ | 抖音粉丝/关注页路径 best-effort |

## 未来扩展

新增平台（如 Instagram Reels、YouTube Shorts）只需：
1. 在 `platforms.py` 新增 `Platform(...)` 实例
2. 完善 `selectors` 字典与对应 Browser Provider
3. 在统一任务能力与校验中注册平台
