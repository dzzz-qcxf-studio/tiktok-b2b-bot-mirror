# Hermes H2 获客任务创建器设计

> 状态：已确认，进入分阶段实现  
> 日期：2026-08-08  
> 范围：仅 H2 目标画像创建 UI 与原子获客建单接线；不包含 H3 结果看板和人工复核工作台

## 1. 背景与问题

H1 已提供受认证的 `POST /api/acquisition/jobs`，可在一个事务中创建 Pipeline Job、
不可变 Campaign 快照和 1—100 个初始关键词。当前 Pipeline 页面仍调用旧的
`POST /api/pipeline/jobs`，因此无法给 Hermes 提供国家、行业、客户角色、关键词和探索预算。

H2 在现有 Pipeline 创建区补齐这条唯一提交链路，保留任务历史、六阶段进度、平台能力
预检和账号策略，不创建第二套任务或路由。

## 2. 方案选择

### 采用：嵌入现有 Pipeline 创建区的分步创建器

- 保留现有账号与 Provider 预检，创建后立即进入同页历史和进度。
- 与已批准的单一 Pipeline Job 架构一致，避免创建数据和 Pipeline 图表数据脱节。
- 将当前创建卡扩展为四步，并对窄屏优化。

不采用独立路由，因为会复制平台、账号、阶段和预检上下文；不采用大弹窗，因为目标画像、
关键词和七项预算在弹窗内过密，移动端与错误定位都较差。

## 3. v0 信息架构

1. **执行范围**：平台、账号策略、Provider/账号能力预检、有序阶段。
2. **目标画像**：国家/地区、语言、行业、产品、客户角色和排除对象。
3. **探索策略**：阶段 01 硬性条件、阶段 02 偏好、初始关键词、关键词混合比例和搜索预算。
4. **确认提交**：以业务语言汇总请求，明确提交后形成不可变快照，再调用原子端点。

只有当前步骤的必填和范围校验通过才能继续；最后提交再执行全量校验。

## 4. 视觉与交互系统

- 颜色沿用 `--brand/--brand-soft/--fg/--muted/--border/--ok/--err`，不新增无语义色相。
- 字体沿用项目全局正文和 `--font-mono`；以现有 4/8px 间距节奏为基础。
- 输入框、选项、卡片和阴影延续现有 Pipeline 层级，不建立新视觉语言。
- 仅使用 160—220ms 的颜色、边框和位移过渡，遵守 `prefers-reduced-motion`。
- 步骤按钮、单选、标签删除和数字输入保留可见焦点；错误使用 `role="alert"`。

## 5. 数据与校验契约

### 5.1 平台、阶段和账号

- 保留 `getPipelineCapabilities()` 与已登录账号预检。
- `stages` 必须包含 `collect`，是六阶段的严格有序子序列；默认全选，且包含 `report`。
- 取消某阶段后仍按六阶段定义顺序提交，不使用点击顺序。
- `auto` 不提交 `accountId`；`specified` 必须提交当前平台已登录账号的 ID。

### 5.2 目标画像和条件分层

- TikTok 必须至少配置一个国家/地区；抖音强制使用 `CN`，不沿用 TikTok 的海外国家。
- 行业和客户角色各至少一项；可输入列表项去除首尾空格并拒绝空白、重复。
- `hardConditions` 只保存阶段 01 排除与必须信号。
- `preferenceConditions` 保存阶段 02 按需核验的员工数、注册资本、上市状态、企业体量和成立年限。
- 文案必须明确：员工数、注册资本和上市状态不是阶段 01 强制淘汰条件。

### 5.3 关键词与预算

- 初始关键词为 1—100 个，支持手工增删，文本和语言联合去重。
- 手工词提交 `source=manual`、`status=new`，同时提交 `text/language/keywordType`。
- 预算默认与后端一致：关键词 20、每词视频 20、每视频评论 30、作者视频 5、页数 10、
  时长 60 分钟、LLM 调用 100；前端使用与后端相同的整数上下界。
- 有效词/新词默认 70/30，两者必须各在 0—100 且合计为 100。

### 5.4 `configSnapshot`

前端明确提交无凭据元数据：

```json
{
  "creatorSchemaVersion": "1.0",
  "creatorSource": "pipeline_ui",
  "targetProfileConfigured": true
}
```

API/Service 继续写入 `businessMode=ai_acquisition` 和 `acquisitionSchemaVersion=1.0`。前端不将 Cookie、
Token、API Key、认证头或 Provider 密钥写入快照。

## 6. 原子 API 与提交后摘要

前端新增 `createAcquisitionJob(payload)`，只调用 `POST /api/acquisition/jobs`。成功后一次获得
`job/campaign/keywords`，保存服务端响应作为创建区内的锁定摘要，再刷新历史并选中返回的 Job。
不允许先创建普通 Job、再调用 Campaign/Keyword 端点。失败时保留输入并允许重试。

锁定摘要展示 Job ID、平台、账号策略、执行阶段、目标画像、条件分层、初始关键词、混合比例
和七项预算。摘要只源于服务端返回的快照，不从可继续编辑的表单反推。

Mock 模式也必须使用同一响应契约，避免将原子建单悄然退化成普通 Job。

## 7. 容错与竞态

- 平台、账号、能力预检和创建请求使用快照值，迟到响应不能覆盖新选择。
- 创建期间锁定步骤导航和提交按钮，防止重复建单。
- 401 继续由现有 Axios 拦截器处理；422 显示校验摘要；409 显示预检/资源冲突。
- 局部错误在字段附近显示；全局错误在创建卡底部显示。

## 8. 测试与验收

1. TikTok 无国家时不能提交，抖音始终提交 `CN`。
2. 任务必须包含 `collect`，阶段按定义顺序提交。
3. 硬性条件与阶段 02 偏好进入不同对象。
4. 关键词可增删，空白和重复被拒绝，不能以 0 个关键词提交。
5. 七项预算的上下界、整数和关键词比例合计验证通过。
6. 请求完整匹配 `POST /api/acquisition/jobs` 契约并含无凭据 `configSnapshot`。
7. 成功后显示基于服务端响应的锁定摘要，并刷新/选中该 Job。
8. 保留能力预检、账号、历史、取消和重试旧功能。
9. 中英文文案、键盘焦点、桌面和 390px 窄屏通过页面检查。
10. 前端专项、全量 Vitest、`type-check`、生产构建和后端原子建单回归通过。

## 9. 非 H2 范围

- 阶段 01 关键词/视频/评论看板；
- 阶段 02 四状态漏斗、候选详情抽屉和人工复核；
- OpenClaw 或第二套 Agent 队列；
- 租户数据隔离补债（仍是 P0 上线阻断）；
- 调整 H1 已定稿的 Campaign/Keyword 后端契约。
